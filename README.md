# Push2Talk

右Optionの長押しで音声入力するmacOS専用のメニューバーアプリです。macOS 13以降で標準音声入力を利用できます。macOS 14以降のApple SiliconではWhisper（MLX）とQwen3-ASRも選べます。

## 表示言語 / Display Language

英語・日本語に対応しています。初期状態ではmacOSの優先言語に従い、対応する言語がなければ英語で表示します。「一般」→「表示言語」で「システムに合わせる」「English」「日本語」を選べます。変更はすぐに反映され、次回起動時にも保持されます。認識言語は標準音声入力ではmacOS側で選び、ローカルエンジンでは発話ごとに自動判定します。

The interface supports English and Japanese. By default it follows your macOS language preferences, falling back to English when neither language is listed. Choose **General → Display Language → Follow System / English / 日本語** to switch immediately. Your choice is saved for future launches. Changing language clears the input test text and count. The local engines detect the language per recording. The system engine uses macOS Dictation settings.

## メニューバーでの設定・About・更新

メニューバーの「クイック設定」から、Enter送信、文字確定の待ち時間、開始ショートカット、状態の表示方法、アイコン、録音中のテキスト、表示言語、ログイン時の起動を変更できます。選択中の項目にはチェックが付き、変更は設定画面にも反映・保存されます。開始ショートカットはmacOS側の設定と合わせてください。

「Push2Talkについて…」でインストール中のバージョンとビルド番号を確認できます。表示値はアプリに組み込まれたInfo.plistから取得します。次の配布版を作る際は`packaging/Info.plist`の`CFBundleShortVersionString`を更新して`mise run bundle`を実行すると、バージョンとビルド番号の両方に反映されます。

「アップデートを確認…」は、操作時だけ公開配布リポジトリ`ut0s/homebrew-push2talk`のGitHub APIで最新の正式リリースを確認します。新しい版がある場合はリリースページを開き、ZIPをダウンロードして、終了後にアプリを置き換えられます。Homebrew利用時の更新コマンドも表示します。自動ダウンロード・自動置換は行いません。公開版がない場合や通信失敗は、最新版の表示と区別されます。

## 認識エンジンとモデル

設定 → 音声入力 → 認識エンジンから切り替えられます。macOS標準は初期設定で、追加ランタイムは不要です。ローカル認識を使うには、macOS 14以降のApple Silicon Macで、使用するモデルに応じてランタイムをインストールしてください。

```sh
brew install uv ffmpeg
uv tool install --python 3.12 mlx-whisper==0.4.3
uv tool install --python 3.12 mlx-qwen3-asr==0.4.4
```

WhisperだけがFFmpegを使用します。必要なランタイムをインストールしたら、設定でエンジンを選び、マイクへのアクセスを許可し、「モデルデータ」から使用するモデルをダウンロードします。Whisperは多言語のbase（約144 MB）とsmall（約481 MB）、Qwen3-ASRは0.6B（MLX、約542 MB）と1.7B（MLX、4-bit、約1.31 GB）を選べます。モデルごとの「削除…」でPush2Talkがダウンロードしたデータを取り除けます。以前にダウンロードした1.7B-hfも「モデルデータ」から削除できます。

ローカルエンジンでは右Optionを離したあとの待ち時間が過ぎると録音を止め、Mac内で文字起こしします。アプリを問わず、アクセシビリティで編集可能と判断できる元の入力欄にフォーカスがあることを再確認し、クリップボード経由でペーストします。ペースト後は元のクリップボードを復元し、その間に新しくコピーされた場合は新しい内容を保持します。ローカル処理中の音声と認識結果は権限を制限した一時フォルダに置き、処理終了時に削除します。

## 動作（macOS標準音声入力）

1. 入力欄にカーソルを置き、右Optionを長押しします。
2. 180ms後に、設定した修飾キーの2回押しを送って標準音声入力を起動します。macOSの開始音・表示を確認してから話してください。
3. 右Optionを離してから800ms待ち、Escapeを送って音声入力を終了します。語尾の認識に猶予を持たせるための待ち時間で、「キーを離してから終了まで」で0.3〜3秒に変更できます（クイック設定にもあります）。開始直後に離した場合は、起動との競合を避けるため、開始トリガーから最低650ms待って終了します。
4. 文字の確定を待ちます（初期値800ms、設定で変更可能）。Enterの自動送信は初期値でオフです。右Optionを離す瞬間に左右どちらかのShiftを押していると、その回だけ設定のオン／オフを反転します（通常オフなら送信、通常オンなら送信しません）。左右両方を押していても同じです。Shiftを先に押してから右Optionを長押しすることもできます。離した後のShift操作では判定は変わりません。同じ入力欄の文字が変わっていれば、Shiftを押したままでも修飾キーなしのEnterを1回送ります。既存の保存済み設定は引き継ぎます。

短いタップでは起動しません。左Optionは通常どおり使えます。右Optionはアプリが有効な間、音声入力専用になります。一時停止すると通常の右Optionに戻ります。

設定画面の「メニューバーアイコン」でマイク（初期値）とトランシーバーを選べます。変更はすぐに反映され、次回起動時も保持されます。どちらのアイコンでも音声入力中・確定待ち・一時停止の状態を表示します。

一時停止中は、状態の表示方法にかかわらず、選択したメニューバーアイコンの右下に一時停止の二重線（Ⅱ）を重ねて表示します。メニューの「再開」で通常のアイコン表示に戻ります。

「録音中のテキスト」では「入力中」（初期値）、「録音中」、「REC」、「テキストなし」を選べます。選択は次回起動時も保持されます。「テキストなし」でも赤いアイコンと録音マークは表示します。

「状態の表示方法」で「メニューバーのみ」（初期値）、「ポップアップのみ」、「両方」を選べます。選択は次回起動時も保持されます。「ポップアップのみ」でも設定を開くための通常のメニューバーアイコンは残り、赤い録音表示や録音中のテキストは出しません。

ポップアップは音声入力の開始時にマウスポインターがある画面の下中央（Dockを避けた位置）に現れます。macOS標準音声入力では赤いマイクを表示し、Whisper・Qwen3-ASRでは録音中のマイク音量を波形で表示します。文字の確定待ちは吹き出しに切り替わり、終了・中断・一時停止で消えます。短いタップでは表示せず、入力先のフォーカスやクリックを妨げません。ローカルエンジンの波形には、録音時に許可したマイク入力を利用します。

右Optionを押していない間は、選択したアイコンに斜線を表示します。押すと斜線が消え、Push2Talkの入力セッションが始まるとアイコンが赤くなり、赤い録音マークと選択したテキストを表示します。離すと終了処理や文字の確定を待っている間も、すぐに斜線を戻します。この表示はPush2Talkの制御状態を表し、OSのマイク稼働状態を直接取得したものではありません。

Escape、Shift以外のほかのキー入力、アプリ・入力欄の切替、スリープ、セッションの終了で中断し、Enterを取り消します。60秒の長押しでも終了し、Enterは送りません。

## ローカルで起動

XcodeまたはCommand Line Tools（Swift 5.9以降）とMiseが必要です。

```sh
# Run once for a trusted checkout
mise trust
mise run test
mise run build-install
```

`mise run build-install`でビルド後にインストール・起動します。起動せずに更新する場合は`mise run build-install --no-launch`を使います。個別に実行する場合は`mise run bundle`、`mise run install-local`を使えます。

タスク一覧は`mise tasks`で確認できます。ビルド・インストールは`mise.toml`、Homebrew公開は`scripts/release-homebrew.sh`で管理し、Miseから呼び出します。

アプリアイコンの元画像は`packaging/AppIcon.png`です。`mise run bundle`で各サイズを生成して`AppIcon.icns`に変換し、アプリに組み込みます。

初回起動時の設定画面で次を設定してください。ローカルエンジンを使用する場合は、手順3と4および上記のランタイム・マイク・モデルを設定してください。

1. macOS「システム設定」→「キーボード」→「音声入力」をオンにする。
2. 音声入力のショートカットを「右Commandキーを2回押す」にする（Push2Talkの初期値）。既存のショートカットを使う場合は、Push2Talk側でも対応する項目を選ぶ。
3. 「プライバシーとセキュリティ」→「アクセシビリティ」でPush2Talkを許可する。キー監視を開始できない場合は「入力監視」も確認する。
4. 「初期設定を完了・権限を再確認」を押す。権限変更が反映されない場合はPush2Talkを再起動する。

設定には右Command（初期値） / Control / 左Option / 左Command / Fnの2回押し、Enter送信、文字確定の待ち時間、ログイン時の起動があります。Fnの合成イベントはキーボード・OS依存があるため実験的です。音声入力のショートカットはOSとアプリで手動で合わせます。OS設定の自動書き換えは行いません。

権限を許可するアプリの場所が安定するよう、通常利用では生成した`Push2Talk.app`を`/Applications`に移してから起動してください。開発用のアドホック署名を作り直した場合は、アクセシビリティ権限の再登録が必要になることがあります。

`mise run install-local`はビルド済みアプリを`/Applications/Push2Talk.app`にコピーして起動します。以降の開発ビルドは`dist/`だけを更新するため、インストール済みアプリの署名は変わりません。インストールし直してアプリを更新した場合は、開発用のアドホック署名では再登録が必要になることがあります。更新をまたいで許可を維持するには、同じApple DevelopmentまたはDeveloper ID証明書による署名を使ってください。

起動せずに更新する場合は`mise run install-local --no-launch`を使えます。キー監視を停止した状態で設定画面を開くには、`open /Applications/Push2Talk.app --args --settings --paused`を実行してください。メニューの「再開」で監視を有効にできます。

### 設定画面のカテゴリ

設定画面は「音声入力」「表示」「権限」「一般」のタブに分かれています。音声入力にはショートカット・初期設定・Enter送信・文字確定待ち、表示には状態の表示方法・アイコン・録音中のテキスト、一般にはログイン時の起動をまとめています。変更は自動保存されます。開いていた設定タブも記憶し、アプリの再起動後や表示言語の変更後も同じページを開きます。

### 設定画面での権限確認

「アプリを再起動」はアプリを完全終了してから、新しいプロセスで起動します。連打や複数箇所からの起動でも、同じユーザーで動作するPush2Talkは1つに制限し、メニューバーアイコンの重複を防ぎます。

設定画面の「権限」タブに「権限とキー監視」を表示します。AltTabAltの権限表示を参考に、色付きのチェック・警告アイコンと「許可済み／未許可」を表示し、それぞれのOS設定へ移動できます。

- アクセシビリティ: 入力欄の確認と右Optionの操作に必要です。
- 入力監視: OSが返す許可状態を表示します。未許可でもアクセシビリティの許可によってキー監視が動作する場合は、その事実も表示します。
- キー送信: 音声入力の開始・終了とEnter送信の許可を確認します。
- キー監視の動作: 実際のイベントタップの状態を確認し、「監視中」「権限待ち」「初期設定待ち」「一時停止中」「開始失敗」を区別します。

確認結果と最終確認時刻は約0.8秒ごとに更新します。「今すぐ再確認」でも更新できます。アクセシビリティが許可されるとキー監視を自動で再試行します。キー送信の事前判定で監視開始まで止めないよう、監視と送信は別々に確認します。「初期設定を完了」を押しても設定画面を閉じず、結果を確認できます。

権限が許可済み・キー監視が「監視中」でも反応しない場合は、設定画面を開いたまま右Optionを押し、「直近の受信」が「右Option」に変わるか確認してください。左Optionと表示される場合はキーボード側の割り当てを確認してください。「未確認」のままならキーイベントが届いていません。パスワード欄やターミナル等のセキュア入力が有効な場合は「セキュア入力で受信停止中」と表示します。パスワード欄から移動するか、該当アプリのセキュアキーボード入力を解除して確認してください。右Optionの受信判定は、左右別のフラグがないイベントにも対応します。

アクセシビリティが許可済みでもキー送信が未許可の場合は、キー送信の「許可を要求」でOSの確認を行ってください。反映されない場合は「アプリを再起動」で、設定画面を表示した状態で再確認できます。入力監視の個別許可がなくてもキー監視が動作している場合は「監視可能」と表示します。権限確認の結果が変化したときだけ、許可状態と監視状態の真偽値をシステムログに記録します。入力内容は記録しません。

macOS標準音声入力のマイク・音声認識の許可はmacOSが管理します。ローカルエンジンを選ぶと、Push2Talkのマイク許可を音声入力タブから設定できます。音声入力の有効化とショートカットはキーボード設定で確認してください。OS上で許可したのに確認結果が変わらない場合は、まずアプリを再起動してください。更新前のバイナリを許可していた場合は、同じ場所の現在のPush2Talk.appを登録し直してください。

設定画面には起動中のアプリのパスと「現在のアプリをFinderで表示」を表示します。同じアプリ名の古い登録が残っている場合は、OS設定の古い項目を「−」で削除し、「＋」からこのアプリを選び直してください。単にスイッチを入れ直すだけでは、古い署名との不一致が解消されない場合があります。

## バージョン管理

バージョンの唯一の管理元は`packaging/Info.plist`の`CFBundleShortVersionString`です。
`P2T_VERSION`による上書き機能は削除しており、環境変数が設定されていても使用しません。

```sh
mise run bump:patch:commit  # Increment patch: 0.1.0 -> 0.1.1
mise run bump:minor:commit  # Increment minor: 0.1.1 -> 0.2.0
mise run bump:major:commit  # Increment major: 0.2.0 -> 1.0.0
```

`bump:patch:commit`・`bump:minor:commit`・`bump:major:commit`は指定した桁を1つ上げ、下位の桁を0に戻し、plistの`CFBundleShortVersionString`と`CFBundleVersion`を同じ値に更新します。更新する桁はコロン区切りのタスク名で指定します。更新したplistだけを`chore(release): bump version to X.Y.Z`で自動コミットします。
実行前に未コミットの変更（ステージ済み・未ステージ・未追跡ファイルを含む）がある場合は、エラーメッセージを表示して停止し、バージョン更新もコミットも行いません。先に変更をコミットするかstashしてください。コミットに失敗した場合はエラー終了し、更新したplistは確認・修正できるよう残ります。
更新後は`mise run release`を実行してください。ビルド・配布処理は常にplistからバージョンを読み取ります。

## Homebrewでの配布

Listo・AltTabAltと同じく、作業用リポジトリと公開配布リポジトリを分けます。
公開先の既定値は`ut0s/homebrew-push2talk`です。公開するのはREADME、Cask、
UniversalアプリのZIPだけで、Swiftソースや作業リポジトリの履歴はコピーしません。

配布物をローカルで準備・確認する場合（GitHubの変更なし）:

```sh
mise run prepare-release
```

`dist/Push2Talk-0.1.0.zip`、SHA-256ファイル、
`dist/homebrew-push2talk/`に公開用READMEとCaskが生成されます。
バージョンは`packaging/Info.plist`を参照します。

`mise run release`の一つのコマンドで、テスト → Universalビルド・署名 → ZIP・SHA-256・Cask生成 → GitHub Release公開 → 公開tapへのコミット・pushまで実行します。AltTabAltと同じく`scripts/release-homebrew.sh`にまとめてあり、`./scripts/release-homebrew.sh`でも直接実行できます。

初回公開は、変更をコミットしてから実行します。

```sh
P2T_CREATE_PUBLIC_REPO=1 mise run release
```

次回以降はバージョンを上げてコミットし、次を実行します。

```sh
mise run release
```

公開後のインストール:

```sh
brew install --cask ut0s/push2talk/push2talk
open -a Push2Talk
```

初期状態のビルドはアドホック署名です。AltTabAltと同様に、ダウンロードしたMacで
初回起動がブロックされる場合の確認手順を公開用README・Caskに含めています。
Developer ID署名と公証にも対応します。
詳細は[配布手順](docs/homebrew.md)を参照してください。
現時点では公開リポジトリ・Releaseの作成は行っていません。

## 制約と確認

macOS標準音声入力の起動完了・認識完了を通知する公開APIは利用していません。起動はショートカット、終了はEscape、確定待ちはタイマーで制御します。macOSの起動待ち時間や認識の遅延があり、物理的に押している期間とマイクの稼働期間が厳密に一致するわけではありません。文字が遅れて確定する場合は待ち時間を延ばしてください。

Enter送信の確認には、アクセシビリティ経由で元の入力欄の値を読みます。値を取得できない独自エディタでは音声入力の開始・終了はできてもEnterは送りません。パスワード欄は対象外です。標準音声入力の音声処理とネットワーク利用はmacOSの設定に従います。Voice Controlが有効な場合は標準音声入力を使用できません。

入力欄の種類やフォーカス情報を取得できない場合も、前面アプリを記録して標準音声入力の開始を試みます。この場合は自動Enterを無効にし、アプリ切替・クリック・キー入力で中断します。入力欄の情報を取得できる場合は、同じ入力欄かどうかも確認します。`--diagnostics`を付けて起動すると、長押し待ち・開始ショートカット送信・開始を見送った理由を標準エラーへ出力します。

音声入力がOS側で先に終了していた場合やショートカットが一致していなかった場合も、終了操作としてEscapeを送るため、入力先のポップアップ等が閉じる可能性があります。

自動テストは長押し、短いタップ、起動直後のリリース、連続イベント、中断、Enterの取消、60秒の終了、Enter無効化を確認します。CIではテスト、Universalビルド、Cask生成を行います。実際の音声認識と入力先アプリの動作は実機確認が必要です。

キー監視は専用スレッドで処理し、イベントを返す前に入力欄の取得・権限確認・画面更新を実行しません。通常キーをそのまま返すこと、長押し・中断の通知を後から順番に処理すること、監視終了時に古い通知を無効にすることも回帰テストで確認します。

実機での確認例:

- テキストエディットで長押しして発話し、離すと認識が終了し、初期設定では改行されず文字だけが残ること。
- 短いタップでは認識を開始しないこと。
- 入力中にEscape、別アプリへの切替、別入力欄のクリックを行うとEnterを送らないこと。
- 左Optionが通常どおり使え、一時停止中は右Optionも通常どおり使えること。
- 初期設定では文字だけが残り、Enterによる送信・決定・改行が行われないこと。通常オフでは左右どちらかのShiftを押したまま右Optionを離すとEnterが送られ、通常オンでは同じ操作でEnterが抑止されること。Shiftを押したまま開始でき、途中で押したり離したりしても中断されないこと。

### 入力処理を変更したときの回帰確認

2026-11-02には、音声入力開始用の修飾キー送信がOSの修飾フラグを書き換え、右Optionを押し続けていても解放と判定する不具合が発生しました。実機では、論理的な右Optionが物理キー状態では左Option側に対応していました。現在は押下ごとに対応する物理キーを確認し、特定できない場合は修飾フラグだけで解放と断定しません。ウィンドウの破棄処理とは別の、解放通知の補完処理にあった問題です。

入力系の修正は、次を確認してから動作確認済みと扱います。

- 自動テストでは、公開のポーリング入口からOS状態の読み取りと長押しセッションを通す。物理キーを保持したまま、開始ショートカットでOptionフラグが消える記録を再現する。内部判定への真偽値入力だけで検証を終えない。
- 自動テストでは、左右の対応変更・左右同時押し・対応不明・解放通知欠落・ShiftによるEnter反転を維持する。
- 実機では、通常の入力欄で3秒以上押し続け、音声入力と録音中アイコンが途中で終了せず、離すと終了することを確認する。設定画面でキー受信が見えるだけでは合格にしない。
- 設定画面の開閉後にも同じ操作を確認する。キーの入れ替えを使う環境では、その設定を有効にした状態でも確認する。
- インストールした実行ファイルが検証対象と一致することを確認し、更新後の権限とキー監視を確認する。許可が引き継がれなかった場合は再登録・再起動後に実機確認を行う。

`mise run test`が成功しても、実音声入力や権限の実機確認を自動的に完了したことにはしません。検証結果には、自動テスト・ビルド・インストール・実機確認をそれぞれ記録します。
