# Push2Talk

右Optionを押している間だけmacOS標準の音声入力を使う、macOS専用のメニューバーアプリです。Swift / AppKitで実装し、外部ライブラリやNode.jsランタイムは不要です。macOS 13以降に対応します。

## 動作

1. 入力欄にカーソルを置き、右Optionを長押しします。
2. 180ms後に、設定した修飾キーの2回押しを送って標準音声入力を起動します。macOSの開始音・表示を確認してから話してください。
3. 右Optionを離すとEscapeを送って音声入力を終了します。開始直後に離した場合は、起動との競合を避けるため、開始トリガーから最低650ms待って終了します。
4. 文字の確定を待ち（初期値800ms、設定で変更可能）、同じ入力欄の文字が変わっていればEnterを1回送ります。Enter送信はオフにもできます。

短いタップでは起動しません。左Optionは通常どおり使えます。右Optionはアプリが有効な間、音声入力専用になります。一時停止すると通常の右Optionに戻ります。

設定画面の「メニューバーアイコン」でマイク（初期値）とトランシーバーを選べます。変更はすぐに反映され、次回起動時も保持されます。どちらのアイコンでも音声入力中・確定待ち・一時停止の状態を表示します。

右Optionを押していない間は、選択したアイコンに斜線を表示します。押すと斜線が消え、Push2Talkの入力セッションが始まるとアイコンが赤くなり、赤い録音マークと「入力中」を表示します。離すと終了処理や文字の確定を待っている間も、すぐに斜線を戻します。この表示はPush2Talkの制御状態を表し、OSのマイク稼働状態を直接取得したものではありません。

Escape、ほかのキー入力、アプリ・入力欄の切替、スリープ、セッションの終了で中断し、Enterを取り消します。60秒の長押しでも終了し、Enterは送りません。

## ローカルで起動

XcodeまたはCommand Line Tools（Swift 5.9以降）が必要です。

```sh
swift test
bash scripts/build-app.sh
bash scripts/install-local.sh
```

初回起動時の設定画面で次を設定してください。

1. macOS「システム設定」→「キーボード」→「音声入力」をオンにする。
2. 音声入力のショートカットを「右Commandキーを2回押す」にする（Push2Talkの初期値）。既存のショートカットを使う場合は、Push2Talk側でも対応する項目を選ぶ。
3. 「プライバシーとセキュリティ」→「アクセシビリティ」でPush2Talkを許可する。キー監視を開始できない場合は「入力監視」も確認する。
4. 「初期設定を完了・権限を再確認」を押す。権限変更が反映されない場合はPush2Talkを再起動する。

設定には右Command（初期値） / Control / 左Option / 左Command / Fnの2回押し、Enter送信、文字確定の待ち時間、ログイン時の起動があります。Fnの合成イベントはキーボード・OS依存があるため実験的です。音声入力のショートカットはOSとアプリで手動で合わせます。OS設定の自動書き換えは行いません。

権限を許可するアプリの場所が安定するよう、通常利用では生成した`Push2Talk.app`を`/Applications`に移してから起動してください。開発用のアドホック署名を作り直した場合は、アクセシビリティ権限の再登録が必要になることがあります。

`install-local.sh`はビルド済みアプリを`/Applications/Push2Talk.app`にコピーして起動します。以降の開発ビルドは`dist/`だけを更新するため、インストール済みアプリの署名は変わりません。インストールし直してアプリを更新した場合は、開発用のアドホック署名では再登録が必要になることがあります。更新をまたいで許可を維持するには、同じApple DevelopmentまたはDeveloper ID証明書による署名を使ってください。

起動せずに更新する場合は`bash scripts/install-local.sh --no-launch`を使えます。キー監視を停止した状態で設定画面を開くには、`open /Applications/Push2Talk.app --args --settings --paused`を実行してください。メニューの「再開」で監視を有効にできます。

### 設定画面での権限確認

「アプリを再起動」はアプリを完全終了してから、新しいプロセスで起動します。連打や複数箇所からの起動でも、同じユーザーで動作するPush2Talkは1つに制限し、メニューバーアイコンの重複を防ぎます。

設定画面の先頭に「権限と動作確認」を表示します。AltTabAltの権限表示を参考に、色付きのチェック・警告アイコンと「許可済み／未許可」を表示し、それぞれのOS設定へ移動できます。

- アクセシビリティ: 入力欄の確認と右Optionの操作に必要です。
- 入力監視: OSが返す許可状態を表示します。未許可でもアクセシビリティの許可によってキー監視が動作する場合は、その事実も表示します。
- キー送信: 音声入力の開始・終了とEnter送信の許可を確認します。
- キー監視の動作: 実際のイベントタップの状態を確認し、「監視中」「権限待ち」「初期設定待ち」「一時停止中」「開始失敗」を区別します。

確認結果と最終確認時刻は約0.8秒ごとに更新します。「今すぐ再確認」でも更新できます。アクセシビリティが許可されるとキー監視を自動で再試行します。キー送信の事前判定で監視開始まで止めないよう、監視と送信は別々に確認します。「初期設定を完了」を押しても設定画面を閉じず、結果を確認できます。

権限が許可済み・キー監視が「監視中」でも反応しない場合は、設定画面を開いたまま右Optionを押し、「直近の受信」が「右Option」に変わるか確認してください。左Optionと表示される場合はキーボード側の割り当てを確認してください。「未確認」のままならキーイベントが届いていません。パスワード欄やターミナル等のセキュア入力が有効な場合は「セキュア入力で受信停止中」と表示します。パスワード欄から移動するか、該当アプリのセキュアキーボード入力を解除して確認してください。右Optionの受信判定は、左右別のフラグがないイベントにも対応します。

アクセシビリティが許可済みでもキー送信が未許可の場合は、キー送信の「許可を要求」でOSの確認を行ってください。反映されない場合は「アプリを再起動」で、設定画面を表示した状態で再確認できます。入力監視の個別許可がなくてもキー監視が動作している場合は「監視可能」と表示します。権限確認の結果が変化したときだけ、許可状態と監視状態の真偽値をシステムログに記録します。入力内容は記録しません。

マイク・音声認識の許可はmacOS標準音声入力が管理するため、Push2Talkからは要求しません。音声入力の有効化とショートカットはキーボード設定で確認してください。OS上で許可したのに確認結果が変わらない場合は、まずアプリを再起動してください。更新前のバイナリを許可していた場合は、同じ場所の現在のPush2Talk.appを登録し直してください。

設定画面には起動中のアプリのパスと「現在のアプリをFinderで表示」を表示します。同じアプリ名の古い登録が残っている場合は、OS設定の古い項目を「−」で削除し、「＋」からこのアプリを選び直してください。単にスイッチを入れ直すだけでは、古い署名との不一致が解消されない場合があります。

## Homebrewでの配布

Listo・AltTabAltと同じく、作業用リポジトリと公開配布リポジトリを分けます。
公開先の既定値は`ut0s/homebrew-push2talk`です。公開するのはREADME、Cask、
UniversalアプリのZIPだけで、Swiftソースや作業リポジトリの履歴はコピーしません。

配布物をローカルで準備・確認する場合（GitHubの変更なし）:

```sh
bash scripts/release-homebrew.sh --prepare
```

`dist/Push2Talk-0.1.0.zip`、SHA-256ファイル、
`dist/homebrew-push2talk/`に公開用READMEとCaskが生成されます。
バージョンは`packaging/Info.plist`を参照します。

初回公開は、変更をコミットしてから実行します。

```sh
P2T_CREATE_PUBLIC_REPO=1 bash scripts/release-homebrew.sh
```

次回以降はバージョンを上げてコミットし、次を実行します。

```sh
bash scripts/release-homebrew.sh
```

公開後のインストール:

```sh
brew install --cask ut0s/push2talk/push2talk
open -a Push2Talk
```

初期状態のビルドはアドホック署名です。AltTabAltと同様に、ダウンロードしたMacで
初回起動がブロックされる場合の確認手順を公開用README・Caskに含めています。
Developer ID署名と公証にも対応します。
詳細は[配布手順](docs/homebrew.md)を参照してください。
現時点では公開リポジトリ・Releaseの作成は行っていません。

## 制約と確認

macOS標準音声入力の起動完了・認識完了を通知する公開APIは利用していません。起動はショートカット、終了はEscape、確定待ちはタイマーで制御します。macOSの起動待ち時間や認識の遅延があり、物理的に押している期間とマイクの稼働期間が厳密に一致するわけではありません。文字が遅れて確定する場合は待ち時間を延ばしてください。

Enter送信の確認には、アクセシビリティ経由で元の入力欄の値を読みます。値を取得できない独自エディタでは音声入力の開始・終了はできてもEnterは送りません。パスワード欄は対象外です。音声・入力内容をファイルに記録しません。音声処理とそのネットワーク利用はmacOS標準音声入力の設定に従います。Voice Controlが有効な場合は標準音声入力を使用できません。

入力欄の種類やフォーカス情報を取得できない場合も、前面アプリを記録して標準音声入力の開始を試みます。この場合は自動Enterを無効にし、アプリ切替・クリック・キー入力で中断します。入力欄の情報を取得できる場合は、同じ入力欄かどうかも確認します。設定画面には、長押し待ち・開始ショートカット送信・開始を見送った理由を表示します。

音声入力がOS側で先に終了していた場合やショートカットが一致していなかった場合も、終了操作としてEscapeを送るため、入力先のポップアップ等が閉じる可能性があります。

自動テストは長押し、短いタップ、起動直後のリリース、連続イベント、中断、Enterの取消、60秒の終了、Enter無効化を確認します。CIではテスト、Universalビルド、Cask生成を行います。実際の音声認識と入力先アプリの動作は実機確認が必要です。

キー監視は専用スレッドで処理し、イベントを返す前に入力欄の取得・権限確認・画面更新を実行しません。通常キーをそのまま返すこと、長押し・中断の通知を後から順番に処理すること、監視終了時に古い通知を無効にすることも回帰テストで確認します。

実機での確認例:

- テキストエディットで長押しして発話し、離すと認識が終了し改行されること。
- 短いタップでは認識を開始しないこと。
- 入力中にEscape、別アプリへの切替、別入力欄のクリックを行うとEnterを送らないこと。
- 左Optionが通常どおり使え、一時停止中は右Optionも通常どおり使えること。
- Enter送信をオフにすると文字だけが残ること。

参照: [Appleの音声入力ガイド](https://support.apple.com/en-gb/guide/mac-help/mh40584/mac)、[Homebrew Cask Cookbook](https://docs.brew.sh/Cask-Cookbook)。
